# Incident Response

## Overview
This runbook defines how to respond when FamilyRoots experiences production incidents.

## What to Document Here
- Severity levels and escalation paths
- Who owns backend, web, mobile, and infra incidents
- How to triage auth, data integrity, deploy, and notification failures
- How to communicate status to users and maintainers

## Current Known Risks
- No explicit incident process is yet documented in the repository.
- Broken clan isolation or contract drift should be treated as high severity.
- Notification failures should not block core read/write flows.
